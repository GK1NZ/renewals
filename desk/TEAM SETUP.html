Team setup: one shared database

For a firm where several brokers work from the same client database. Each broker signs in with their Microsoft 365 work account. The data sits in one shared folder in the firm's own Microsoft 365, so nothing is held by an outside provider.

What you need
  • A Microsoft 365 work account for every broker, in the same organisation.
  • Somewhere to host this folder at an https web address. Sign-in does not work from a folder on disk.
  • About 20 minutes from whoever administers the firm's Microsoft 365.

1. Host the folder (IT)

Upload the whole BrokerDesk folder, unchanged, to any static web host the firm controls: Azure Static Web Apps, an existing website, or similar. Note the address of index.html, for example https://desk.yourfirm.co.nz/index.html.

2. Register the app in Microsoft Entra (IT)

  1. Go to entra.microsoft.com, then Applications, App registrations, New registration.
  2. Name: Broker Desk. Supported accounts: this organisation only.
  3. Redirect URI: choose Single-page application and enter the exact address of index.html from step 1.
  4. Under API permissions add these Microsoft Graph delegated permissions, then grant admin consent:
    User.ReadShows who is signed in.
    Files.ReadWrite.AllReads and writes the shared BrokerDesk folder, as the signed-in broker.
    Mail.ReadWriteCreates email drafts in the broker's Outlook. Nothing is sent.
    Calendars.ReadWriteAdds chase reminders to the broker's calendar.
  5. Copy the Application (client) ID and the Directory (tenant) ID.

All permissions are delegated: the app can only do what the signed-in broker can already do. There is no server and no stored password.

3. Create the shared database (first broker)

  1. Open the web address. On the first screen open Team: one shared database for several brokers.
  2. Paste the Application ID. Set the sign-in authority to https://login.microsoftonline.com/ followed by the tenant ID. Sign in.
  3. Choose In my own OneDrive. This creates a folder called BrokerDesk.
  4. In OneDrive, share that BrokerDesk folder with the other brokers, with Can edit, and copy the link. For a database that does not depend on one person's account, create the folder in a SharePoint team site instead and use its link in step 4 for everyone.

4. Invite each broker

  1. Share the BrokerDesk folder with them, with Can edit (step 3).
  2. In Broker Desk open Settings, then Copy invite link, and send them the link.
  3. They open the link and press Sign in with Microsoft. That is all: no IDs to paste. A short tour shows them around, and Settings is where they add their mobile for their email sign-off.

How it behaves with several brokers

  • Every client carries its broker's name. Today and Calendar show your own clients first, with an Everyone button. Find and Clients always search the whole firm.
  • Changes from other brokers appear within about 20 seconds.
  • If two brokers save at the same moment, Broker Desk re-reads and applies both. If two people edit the same field of the same client, the later save wins.
  • Documents are stored as files in the same shared folder.
  • A broker who uses Gmail for client email can set Settings, Email drafts to On this device. They still sign in with the Microsoft account to reach the database.

Moving existing work in

A broker who has been using Broker Desk on their own device can bring it across: take a backup there, then ask for it to be imported. Loading one person's backup over the shared database replaces what is in it, so do this once, before others start.

Backup

The shared folder is covered by Microsoft 365 version history and the recycle bin. More, Back up everything also saves a copy of the client records to a file.
